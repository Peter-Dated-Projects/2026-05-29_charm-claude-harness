## Changes in src/console/app.tsx
- Extend `type Tab` to include `"files"`.
- App shell `useInput`: `4` sets tab to `files`; include `files` in the Tab / Shift-Tab cycle order (after `agents`); add a tab-bar entry ` 4·Files `.

  - Vertical split identical to ArtifactsTab: `<FileTree>` panel on top (height = the user-adjustable, `+`/`-`-resizable row count, reusing ArtifactsTab's clamp/`filesRowsEff` math), markdown viewer below. The PARENT owns the bordered Box + panel header for the tree (FileTree renders rows only, per its contract).
  - Track the selected file path via `FileTree`'s `onOpenFile` callback in local state; `onOpenFile(null)` (cursor on a dir) clears the viewer selection. Feed the path to `useFileContent` + `renderMarkdown` exactly as ArtifactsTab does.
  - Pass `isActive={inputActive}` into `<FileTree>`.

## CRITICAL: input-handler key-set partition (this was the original blocker)
Ink delivers EVERY keypress to EVERY mounted `useInput` whose `isActive` is true. In FilesTab, `FileTree`'s `useInput` and the viewer's scroll `useInput` both mount together while the tab is focused — `inputActive` gates the whole tab, not between them. Therefore the two handlers' key sets MUST be disjoint, or shared keys double-fire.
- `FileTree` (from T-006) owns: `j`/`k`/up/down, Shift+up/down, Enter/right, left/`h`, `r` (tree refresh), `g`/`G` (tree cursor top/bottom).
- The Files-tab viewer owns ONLY: mouse wheel, Space/`b` (page), `^d`/`^u` (half-page). It MUST NOT bind `g`/`G` or `r` — those belong to the tree here. (This differs from ArtifactsTab, where `g`/`G` scroll the viewer and `r` resets selection; that is fine because ArtifactsTab has a single combined handler. In Files, `g`/`G`=tree cursor and `r`=tree refresh by design — do not “fix” this to scroll the viewer.)

## Binary placeholder
- If the selected file is binary (`isBinaryFile(path)` from file-tree.tsx returns true), render `(binary file — N bytes)` in the viewer instead of decoding/`renderMarkdown`. `isBinaryFile` returns a boolean only — get N from `statSync(path).size`, wrapped in try/catch so a file deleted between selection and stat does not throw during render (fall back to `(binary file)` with no size, or clear).

## Reuse, don't duplicate
- Factor the viewer's scroll STATE + panel RENDERING (the markdown-row slice, scroll indicator, bottom hint, padding) shared by ArtifactsTab and FilesTab into one local helper/component within app.tsx. Do NOT hoist the KEY BINDINGS into it: ArtifactsTab keeps binding `g`/`G`→viewer and `r`→reset-selection in its OWN `useInput` (the existing `r` reset at the ArtifactsTab input handler must stay local, not leak into the shared helper); FilesTab binds only Space/`b`/`^d`/`^u`/wheel to the shared scroll setters.
- ArtifactsTab's existing behavior MUST NOT change — same flat list, same stage-aware auto-selection, same bindings, same `r`=reset.
- Leave the stage-aware auto-flip-to-Approvals logic untouched.

- [ ] Selecting a file renders it in the viewer; selecting a dir clears the viewer selection; a binary file shows `(binary file — N bytes)` with N from `statSync`, guarded against deletion.

## Edge cases
- Selection clamp: if a live tree update or collapse drops the selected file, clear or re-resolve the viewer selection rather than rendering a stale/missing path.
- Resize: the `+`/`-` list-resize and terminal-resize handling must work in FilesTab the same as ArtifactsTab (reuse the same clamp math, don't fork it).
