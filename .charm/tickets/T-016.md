## Goal
Investigate how closely a VSCode-style UI (activity bar, side panel, editor area, bottom terminal panel, status bar) can be replicated in each top Rust framework. Spawn subagents to research each framework in parallel.

## VSCode UI patterns charm needs
1. **Activity bar** (left icon strip — Agents / Tickets / KB / Proposals / Settings)
2. **Side panel** (collapsible tree — ticket list, KB file tree, agent list)
3. **Editor/main area** (tabbed markdown viewer, ticket detail, proposal editor, agent log streaming)
4. **Bottom panel** (approval queue, status log)
5. **Status bar** (session info, agent count, model, live cost ticker)
6. **Command palette** (fuzzy search across tickets/KB/agents)
7. **Diff view** (for proposals / KB changes)
8. **Inline terminal** (streaming agent output, possibly embedded tmux pane)

## For each Rust framework
- Does it have a built-in panel/dock/tab system, or must it be hand-rolled?
- Is there a crate for a VS Code-style activity bar or are we building from scratch?
- Can it embed a real terminal emulator (alacritty's `vte` crate? `crossterm`?) in a pane?
- Markdown rendering with syntax highlighting — what crates? (`comrak` + `syntect`?)
- Code editor widget — is there a Monaco equivalent? (`helix`-style `ropey` + custom?)
- How does each framework handle resizable split panes?

## Prior art to check
- **Zed** is a production VSCode-competitor built on GPUI — examine their architecture for lessons
- **Lapce** is built on Floem — examine their panel/tab system
- **Helix** is TUI-only but its buffer/window model is instructive
- Any VSCode extensions or forks that expose their layout as a library?

## Deliverable
For each framework: can it do VSCode-style layout (yes/partial/no), what gaps exist, effort to close them. Write to `.charm/proposals/PROP-vscode-layout-feasibility.md`.
