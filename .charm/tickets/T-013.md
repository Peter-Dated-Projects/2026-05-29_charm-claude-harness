## Goal
Survey every serious Rust UI framework and score them across the dimensions charm needs. Spawn subagents to go deep on each framework in parallel.

## Frameworks to cover (at minimum)
- **Tauri** (web renderer + Rust backend, most mature)
- **Dioxus** (React-like, can target desktop/web/TUI)
- **Slint** (declarative, GPU-accelerated, commercial-friendly license)
- **Iced** (Elm-like, wgpu-based)
- **egui** (immediate mode, wgpu/OpenGL)
- **GPUI** (Zed's framework — GPU-accelerated, retained mode, production-proven)
- **Floem** (reactive, wgpu)
- **xilem** (Google's experimental reactive framework)
- **Wails** (Go, but note it for contrast with Tauri)

## For each framework, research and report
1. **Rendering backend** — WebView? wgpu? OpenGL? CPU? Implications for macOS/Windows/Linux.
2. **Performance** — startup time, memory footprint at idle, CPU at 60fps animation. Find benchmarks or produce estimates.
3. **Maturity & stability** — production use cases, GitHub stars, last commit, breaking-change cadence.
4. **Package ecosystem** — what crates are available for: markdown rendering, code highlighting, tree views, diff views, terminal emulation, force-directed graphs, drag-and-drop.
5. **Ease of development** — hot reload? compile times? dev ergonomics?
6. **macOS distribution** — code signing, notarization, .app bundle, any known issues.

## Deliverable
A scored comparison table (rows = frameworks, cols = dimensions) and a short narrative on the top 2-3 candidates. Write to `.charm/proposals/PROP-rust-ui-framework-comparison.md`.
