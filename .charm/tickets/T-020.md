## Context

charm's native app is a Tauri v2 + React desktop app. The primary surface is a React Flow 2D graph of the live agent hierarchy. Interaction is mouse-primary with a Spotlight-style command palette for keyboard power users.

All output from this ticket goes to the `charm/native-ui` worktree. Write proposals to `.charm/worktrees/native-ui/.charm/proposals/` and track notes to `.charm/worktrees/native-ui/.charm/kb/tracks/native-ui/`. Do NOT write to the main `.charm/proposals/` directory.

## Interaction patterns to design

### 1. Node click → detail drawer
When the user clicks an agent node, a detail drawer slides in from the right (or bottom). Design:
- What information is shown? (agent log stream, current ticket title+body, plan steps, elapsed time, status)
- How is the log streamed? (incremental WebSocket push into a virtualized list)
- Actions available in the drawer: kill agent (with two-press guard), approve/reject gate, view ticket in full
- Drawer width and whether it overlays or pushes the canvas
- Keyboard: Escape to dismiss

### 2. Command palette (Cmd+K)
Spotlight-style fuzzy search across:
- Live agents (by role, ticket ID, status)
- Tickets (by ID, title, status)
- KB notes (by filename, summary)
- Worktrees / suborchestrator contexts
- Actions (kill agent, approve gate, spawn worker, open settings)

Library recommendation: `cmdk` (the same library used in Vercel, Linear, Raycast web). Design the item groups, keyboard navigation, and what happens on selection.

### 3. Suborchestrator drill-down
When a suborchestrator is running in a worktree, double-clicking its node should 'enter' that context:
- Does the canvas zoom into the suborchestrator's subgraph (animate in)?
- Or does it navigate to a new canvas view for that worktree context?
- A breadcrumb at the top shows: `main > worktree:native-ui > suborchestrator-002`
- Back navigation via breadcrumb or Backspace/Escape

### 4. Approval gate UX
Approval gates are the most time-sensitive interaction. Design:
- The gate node on the canvas (visually urgent)
- When a gate arrives, does the app send a system notification (Tauri notification API)?
- The approval UI: what does the user read before approving? (gate message, which agent requested it, what action it will take)
- Approve / reject actions: buttons in detail drawer, or keyboard shortcut (Y/N) when gate node is focused?
- How is the decision sent back to the daemon? (Tauri invoke → daemon RPC `approve_gate`)

### 5. Settings / session info
- Where does session info live? (status bar at bottom: session UUID, model, agent count, uptime)
- Settings panel: model selection, tmux-vs-embedded-terminal toggle, auto-approve rules
