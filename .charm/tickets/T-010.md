## What the doc must cover
Organize by scope, one table per scope:
1. **Global / app shell:** `1`/`2`/`3`/`4` tab selection, `Tab` / `Shift-Tab` cycle (document the exact cycle order, including where `files` sits), `:q` quit, `:a` detach.
2. **Artifacts tab:** file-list nav (`j`/`k`/up/down), `+`/`-` resize, viewer scroll (Space/`b` page, `^d`/`^u` half-page, `g`/`G` top/bottom, wheel), `r` reset-selection.
3. **Files tab:** the FileTree keymap — `j`/`k`/up/down (cursor), **Shift+up / Shift+down (jump to prev/next FILE, skipping directories)**, Enter/right (expand dir or open file), left/`h` (collapse or move to parent), `r` (refresh tree + re-read gitignore), `g`/`G` (tree cursor top/bottom); and the Files-tab viewer keys (Space/`b`, `^d`/`^u`, wheel ONLY). Call out explicitly that in the Files tab `g`/`G`/`r` act on the TREE (not the viewer) — this differs from the Artifacts tab — because both input handlers co-mount and their key sets are partitioned to avoid double-firing.
4. **Approvals tab:** `j`/`k` / up/down navigate, `y`/`a` approve, `n`/`r` reject.
5. **Agents tab:** `j`/`k` / up/down navigate, `d` dismiss done/failed, `x`-`x` (double-press) kill running.
