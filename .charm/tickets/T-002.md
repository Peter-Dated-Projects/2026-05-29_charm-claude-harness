## Background

This ticket validates the harness worktree feature: the orchestrator spun up an
isolated git worktree at `.charm/worktrees/test-beta/` on its own branch, and a
worker agent made a demo change inside it. The goal is to confirm the change
landed correctly and that working inside a worktree does not bleed into the main
tree.

## Acceptance criteria

- [ ] `.charm/worktrees/test-beta/` exists and is a valid git worktree
- [ ] `.charm/worktrees/test-beta/src/reverse.js` contains exactly the line:
      `// test-beta: added a comment to reverse.js for worktree demo`
- [ ] The line is the last line of the file (appended, not inserted mid-file)
- [ ] No other edits appear in `git diff` relative to the worktree's base commit
- [ ] `src/reverse.js` in the main tree is unchanged (worktree isolation holds)

## Verification results (reviewer)

- Worktree `.charm/worktrees/test-beta/` confirmed present
- `src/reverse.js` in the worktree reads:
  ```
  export function reverse(s) {
    return s.split("").reverse().join("");
  }
  // test-beta: added a comment to reverse.js for worktree demo
  ```
- Comment text matches expected string exactly
- Commit `5d6a352` ("test: demo comment in reverse.js (beta worktree)") is the
  only commit beyond main; no other files touched
- Main tree `src/reverse.js` is unmodified (3-line file, no comment)

All acceptance criteria pass.

## Edge cases and failure modes

- If the worktree directory is missing entirely: `git worktree list` will not
  show it; the fix is to re-run the worktree creation step.
- If the comment text differs (wrong branch tag, typo): the line comparison
  fails; a worker must amend or force-push the worktree branch.
- If extra files were modified: `git diff HEAD~1` inside the worktree reveals
  scope creep; those changes must be reverted before the ticket can close.
- If the main tree `src/reverse.js` is also modified: worktree isolation was
  violated; investigate whether the agent ran in the wrong cwd.
