Create src/reverse.js exporting a single named function reverse(s) that returns s split into chars, reversed, and joined back. No external dependencies. File must export exactly one function.

## Background

This ticket is part of a harness self-test that exercises the full charm pipeline (tickets, dep/scope solver, review agents, tester, gates). `reverse(s)` is one of two utility functions (`upper` is the other, T-A) that `cli.js` (T-C) dispatches to based on argv; T-C depends on both being present before it can be written.

## Acceptance criteria

- [ ] `src/reverse.js` exists at the declared path.
- [ ] File exports exactly one named symbol — `reverse` — and nothing else.
- [ ] `reverse("hello")` returns `"olleh"`.
- [ ] `reverse("")` returns `""` (empty string roundtrips cleanly).
- [ ] `reverse("a")` returns `"a"` (single character is a no-op).
- [ ] No `require`/`import` of any external package; only the JS standard library.
- [ ] Export style (CommonJS `module.exports = { reverse }` or ESM `export function reverse`) is consistent with `src/upper.js` produced by T-A.

## Edge cases and failure modes

- A naive `s.split("").reverse().join("")` works for ASCII but will corrupt Unicode surrogate pairs and multi-codepoint emoji sequences. Acceptable here — PROJECT.md explicitly calls the code trivial and non-production.
- Exporting a default (`export default function reverse`) instead of a named export will cause T-C's import to silently resolve to `undefined` and `node cli.js reverse hello` will fail at runtime.
- If the file accidentally exports additional symbols, the "exactly one export" acceptance criterion fails and a tester agent will reject it.

## Refined touches

- `src/reverse.js` only — this ticket must not touch `cli.js`, `src/upper.js`, or any test/config file.
