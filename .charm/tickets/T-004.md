## Edge cases and failure modes

- **File does not exist yet:** `src/upper.js` is created by T-001. If the worker runs before T-001 completes (scope serialization failure), the file will be missing. The worker must confirm the file exists and bail with a `failed` status if it does not.
- **Malformed JSDoc breaks syntax:** A multiline JSDoc block inserted without a trailing newline or with unclosed `*/` will cause a parse error. Validate with `node -e "require('./src/upper.js')"` after writing.
- **Overwriting T-001's implementation:** The worker must edit only the JSDoc block and must not alter the function body or export statement — a diff check against the pre-edit content is a reasonable guard.
- **Concurrent write race:** If scope serialization is broken and both T-001 and T-004 run simultaneously, T-004 may write JSDoc to an empty or partially-written file. This is the failure mode the ticket is designed to surface; the tester should verify the final file contains both the implementation and the JSDoc.
