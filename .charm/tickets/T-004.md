## Goal
Investigate best practices for documenting CLI-based developer tools, specifically multi-agent orchestration systems. This research feeds directly into updating the charm docs under docs/.

## Tasks
1. Use WebSearch to find 3-5 authoritative sources on developer tool / CLI documentation best practices (style, structure, completeness, onboarding flow).
2. Pull concrete examples from well-documented CLI tools: tmux, docker, kubectl, gh (GitHub CLI). What sections do they include? How do they handle getting-started vs reference vs conceptual docs?
3. Identify common anti-patterns (docs that rot, missing troubleshooting, unclear prerequisites, etc.).
4. Note any patterns specific to tools that orchestrate other processes or have a daemon/client architecture.

## Output
Write your findings to `.charm/kb/research-cli-doc-practices.md`. Structure it as:
- Key principles (bullet list)
- Section structure patterns (with examples from real tools)
- Anti-patterns to avoid
- Specific recommendations for charm's docs

Do NOT edit any files under docs/ — that is the implementation swarm's job.
