## Context

## What to design

### Phase breakdown
Break the build into phases where each phase ships something runnable:

**Phase 0: Tauri scaffold + daemon bridge**
Get a Tauri app window that can connect to a running `charmd` and display raw JSON from the `status` RPC call. Establishes the build pipeline (Rust + Vite + TypeScript), the IPC mechanism, and verifies the daemon connection works from a Tauri WebView context.

**Phase 1: Live graph (read-only)**
React Flow canvas showing the agent hierarchy from live daemon data. Nodes update in real-time as agents are spawned/change state. Pan, zoom, dagre auto-layout. No interaction yet beyond navigation.

**Phase 2: Core interactions**
Node click → detail drawer with log streaming. Command palette (Cmd+K). Approval gate UX. Kill agent. This is the first phase where the native app is functionally equivalent to the current TUI console.

**Phase 3: Suborchestrator drill-down**
Double-click suborchestrator node to enter its worktree subgraph. Breadcrumb navigation. This requires the multi-daemon connection design from T-021.

**Phase 4: KB and proposals browser**
A panel or view for browsing the KB and proposals without leaving the app. Markdown rendering. Closes the gap with the current console's Artifacts tab.

**Phase 5: OTA update + distribution**
Code signing, notarization, auto-update mechanism (custom multi-binary atomic swap per PROP-ota-update-strategy.md). The app is distributable.

### For each phase
- What is built exactly (components, Tauri commands, daemon changes if any)
- Estimated effort in days (solo developer, TypeScript/React fluency assumed, Rust is thin backend)
- What is the exit criterion (how do you know the phase is done?)
- What dependencies from earlier phases are required
- What can be deferred to a later phase

### v1 definition
What is the minimum set of phases that constitutes a v1 that replaces the current TUI console for daily use? (Probably Phases 0-2, possibly Phase 3.)

### Technology decisions to lock in
- React Flow version (v11 / v12 — check current stable)
- Layout library: dagre vs `@dagrejs/dagre` vs `elkjs` — which integrates most cleanly with React Flow?
- State management: Zustand? Jotai? Plain React context? (Given graph state is complex and updated frequently)
- Tauri IPC vs daemon HTTP/WS — confirm recommendation from T-021
- Terminal emulator for agent logs: xterm.js inside the detail drawer, or a virtualized text list (simpler, no PTY needed since logs are just text lines)?
