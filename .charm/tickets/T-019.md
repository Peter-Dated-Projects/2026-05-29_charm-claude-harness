## Context

charm is building a native desktop app (Tauri v2 + React) where the primary UI is a 2D spatial DAG visualized with React Flow. The graph shows the live agent hierarchy: orchestrators spawn workers, reviewers, investigators, and suborchestrators. Suborchestrators correspond to worktree contexts and can have their own sub-graphs.

All output from this ticket goes to the `charm/native-ui` worktree. Write proposals to `.charm/worktrees/native-ui/.charm/proposals/` and track notes to `.charm/worktrees/native-ui/.charm/kb/tracks/native-ui/`. Do NOT write to the main `.charm/proposals/` directory.

## What to design

### Node types
Design the visual appearance and information density for each node type:
- **Orchestrator** — root node, always present, shows session info + active ticket count
- **Worker** — shows current ticket ID, status (running/blocked/done/failed), elapsed time
- **Reviewer** — similar to worker but visually distinct role
- **Investigator** — similar to worker
- **Suborchestrator** — visually distinct as a 'container' that can be entered; shows worktree branch name, child agent count
- **Approval gate** — not an agent but a node type: appears when a gate is waiting, visually urgent (pulsing border? red accent?)

### Edge types
- Spawn edge (orchestrator → agent): directed arrow showing the spawn relationship
- Dependency edge (ticket → ticket, shown when relevant): dashed?
- Worktree edge (orchestrator → suborchestrator): thicker / different color to signal context boundary

### Node states
For each node: how does it look when running / idle / blocked / done / failed / awaiting approval?

### Layout
- React Flow with dagre (hierarchical top-down layout) as the default auto-layout — fits the spawn tree shape better than force-directed for a strict hierarchy
- Force-directed as an alternative mode (toggle) for free exploration
- Nodes should be draggable; positions persist per session

### React Flow specifics
- What custom node components are needed? (one per node type, or a generic node with variants?)
- What React Flow features are used: `useNodesState`, `useEdgesState`, `MiniMap`, `Controls`, `Background`?
- How are node updates streamed in? (WebSocket message → update node data → React Flow re-renders)
- What is the handle (connection point) placement on each node?

## Deliverable
A detailed design spec for the graph layer. Include ASCII mockups of each node type. Write to `.charm/worktrees/native-ui/.charm/proposals/PROP-graph-node-design.md`.
