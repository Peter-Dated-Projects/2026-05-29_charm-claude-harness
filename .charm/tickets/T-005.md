## Background

cli.js is the integration point for the string-utils harness smoke test: it wires
together the two upstream modules (T-001, T-002) and exposes them as a minimal
command-line interface so the pipeline's tester can validate end-to-end behavior
with `node cli.js upper <str>` and `node cli.js reverse <str>`.

## Acceptance criteria

- [ ] File is named `cli.js` at the repo root (not inside `src/`).
- [ ] Imports `upper` from `./src/upper.js` using a named import (CommonJS `require` or ESM `import`).
- [ ] Imports `reverse` from `./src/reverse.js` using a named import.
- [ ] When `process.argv[2]` is `'upper'`, prints `upper(process.argv[3])` to stdout followed by a newline.
- [ ] When `process.argv[2]` is `'reverse'`, prints `reverse(process.argv[3])` to stdout followed by a newline.
- [ ] No external `npm` dependencies — only Node.js built-ins and the two local modules.
- [ ] `node cli.js upper hello` outputs `HELLO`.
- [ ] `node cli.js reverse hello` outputs `olleh`.

## Edge cases and failure modes

- **Missing command** (`node cli.js` with no argv[2]): argv[2] is `undefined`; passing it to `upper`/`reverse` will call `.toUpperCase()` or `.split()` on `undefined` and throw. The ticket scope does not require error handling, but the worker should be aware — a guard is acceptable if it avoids a confusing crash.
- **Missing input string** (`node cli.js upper` with no argv[3]): argv[3] is `undefined`; same crash risk as above. Out of scope to handle, but worth noting so the tester uses well-formed invocations.
- **Unknown command**: anything that is neither `'upper'` nor `'reverse'` silently does nothing (no branch matches). Acceptable for this smoke test; no error output required.
- **Empty string input** (`node cli.js upper ""`): valid — `"".toUpperCase()` returns `""` and `"".split("").reverse().join("")` returns `""`. Should print an empty line.
- **Module resolution**: depends on T-001 (`src/upper.js`) and T-002 (`src/reverse.js`) being present. If either is missing the process will throw at import time. The daemon's dep solver should prevent this, but the worker must not inline the module logic.
