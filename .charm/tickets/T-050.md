SCOPE (the Rust bridge crate -- buildable on the daemon's TODAY status, no daemon-source edits):
1. New crate `crates/charm` + `crates/charm/src/charm_bridge.rs`; add to `[workspace.members]`/`[workspace.dependencies]`.
2. Types per spec section 1.0 (snake_case serde): TicketFrontmatter, AgentRecord (note: `worktree_name`, ~always None today), ApprovalGate, StatusSnapshot (the 3 fields status returns: tickets, agents, pending_approvals), SessionMeta, and CharmState (StatusSnapshot + coordination + session; sub_orchestrators empty for now -- the daemon doesn't return it yet, that's the deferred T-041 backend).
3. Unix-socket JSON-RPC CLIENT per spec section 2.1: newline-delimited `{id,method,params}` frames, per-call connection, id-correlated reads, backpressure-safe (loop on partial reads; resend unwritten tail on drain -- status replies exceed 8KB). Socket detection at `.charm/run/<uuid>/sock`.
4. Poll loop (1500ms): `status` + `read_coordination` + read `meta.json`; fold into one tick; `apply()` diff per spec 3.1 with `on_agent_spawned` firing for newly-seen agent ids BEFORE the swap (pass the whole &AgentRecord).
5. inject socket SERVER (second listen socket, e.g. `.charm/run/<uuid>/inject.sock`) per spec 2.3 option (a): receive `inject_text {agent_id, text}`. Dispatch via a REGISTERED handler trait/callback (Phase 4 supplies the real terminal write) with the tier logic from spec 3.2: agent_id=="main-001" -> Orchestrator (idle-gated), role==suborchestrator -> SubOrchestrator (idle-gated), else Leaf (direct). For multi-line text the handler contract must use the bracketed-paste path (Spike 1 + spec 3.3: Zed's `Terminal::paste()` already wraps in ESC[200~..ESC[201~ when the REPL is in bracketed-paste mode -- do NOT use raw input for multi-line).
6. Wire into `crates/zed/src/main.rs`: instantiate CharmBridge on startup ONLY when a `.charm` session socket is detected; no-op cleanly otherwise so stock zed still launches (graceful fallback, spec 2.3 registration note).

OUT OF SCOPE (deferred, do NOT do here): the daemon-SOURCE change that teaches the daemon to PUSH inject_text (routing the 3 sendText call-sites) -- that edits the live harness and is tracked separately (T-041 family). The bridge's inject socket server should LISTEN correctly; it just won't receive until the daemon is taught to push. Also out of scope: the hierarchy backend (parent_id/sub_orchestrators) -- T-041.

GATE: `cargo build -p zed` GREEN with the new crate wired in. RESUMABLE: the crate is sizable -- if low on context, report what compiles + what remains + next piece. Leave changes uncommitted. Record decisions/surprises in the ticket + KB. DONE when crates/charm compiles, is wired into zed startup behind charm-session detection, and `cargo build -p zed` is green.
