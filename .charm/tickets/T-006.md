## Goal
Read every file under docs/ and the root README.md, then produce a detailed gap and quality audit. This feeds the implementation swarm that will update the docs.

## Tasks
1. Read all files:
   - docs/README.md
   - docs/operating/getting-started.md
   - docs/operating/running-a-session.md
   - docs/operating/modes-and-models.md
   - docs/operating/cli.md
   - docs/operating/keybindings.md
   - docs/operating/troubleshooting.md
   - docs/developing/architecture.md
   - docs/developing/mcp-tools.md
   - docs/developing/build.md
   - docs/developing/knowledge-base.md
   - docs/developing/preflight.md
   - docs/design/parallelization.md
   - docs/design/phasing-sequencing.md
   - README.md (root)

2. For each file, assess:
   - Is it complete? Are there placeholders, TODOs, or shallow sections?
   - Is it accurate relative to the code in src/? (spot check key claims)
   - Is it consistent with other docs (terminology, cross-links, diagrams)?
   - Is the onboarding flow logical for a new user?
   - Is terminology consistent (e.g. 'ticket' vs 'task', 'stage' vs 'phase', 'gate' vs 'approval')?

3. Cross-link audit: every internal link in docs/ — does it resolve to a file that exists?

## Output
Write your findings to `.charm/kb/audit-existing-docs.md`. Structure it as:
- Per-file assessment table (file | completeness | accuracy | consistency | issues)
- Terminology inconsistencies found
- Broken or missing cross-links
- Top 5 highest-priority gaps to fix
- Suggested new docs that don't exist yet but should

Do NOT edit any files under docs/ — that is the implementation swarm's job.
