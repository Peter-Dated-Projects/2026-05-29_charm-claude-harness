Create a new, self-contained tree module for the console's upcoming Files tab. NEW FILE only — do not edit app.tsx (that is the next ticket's job).

Read first: `.charm/PROJECT.md` (the Files-tab spec, authoritative) and `.charm/proposals/PROP-file-explorer-tab.md`. Skim the existing `src/console/app.tsx` ArtifactsTab to match the project's Ink idioms (Box/Text, `wrap="truncate-end"`, useInput, chokidar usage).

## Background / motivation

The Artifacts tab today shows a flat, hard-coded list (PROJECT.md, COORDINATION.md, `.charm/tickets/*.md`); there is no way to browse proposals, KB, prompts, scratchpad, or arbitrary agent output without dropping to a shell. This ticket builds the reusable tree component that the Files tab (next ticket) wires into `app.tsx`. It is deliberately extracted to its own file so the tree logic and the app-shell wiring can be split without two workers colliding on `app.tsx`. This ticket owns ONLY the component + helpers and their stable export contract; the next ticket owns the viewer reuse and tab registration.

## What to build

A module exporting a keyboard-driven, VS Code-style directory tree as an Ink component, plus the helpers the integration ticket needs.

### Exports (this is the contract the next ticket consumes — keep it stable)
- `export type TreeNode = { path: string; name: string; isDir: boolean; expanded?: boolean; children?: TreeNode[]; depth: number }`
- `export function isBinaryFile(path: string): boolean` — null-byte sniff of the first chunk (e.g. read first 4KB, true if it contains a 0x00 byte or fails to decode as UTF-8). Used by both the tree (dim rows) and the viewer (placeholder).
- `export function FileTree(props: { root: string; height: number; isActive: boolean; onOpenFile: (path: string | null) => void }): JSX.Element` — renders ONLY the tree panel rows (indented, with box-drawing prefixes); the PARENT owns the bordered Box, the panel header, and the panel height. `height` is the visible-row capacity to window into, mirroring `filesRowsEff`/`visibleFiles` in ArtifactsTab. Calls `onOpenFile(absPath)` when a file is opened/selected and `onOpenFile(null)` when the cursor sits on a directory.
  - IMPORTANT: never call `onOpenFile` (a parent setState) during render — that triggers React's "setState during render of another component" warning. Fire it from the `useInput` handler and/or a `useEffect` keyed on the cursor's current node, never inline in JSX.
  - Gate `useInput` with `{ isActive }` (same pattern as ArtifactsTab) so key handling is off when the tab is not focused.

### Behavior
- **Lazy tree:** read a directory's children only when it is first expanded, via `readdirSync(dir, { withFileTypes: true })`; use `Dirent.isDirectory()`. Collapse drops children from state.
- **Visible rows:** derive a flat array by descending only into expanded dirs; a numeric cursor indexes it. Scroll the window to keep the cursor visible within `height` rows (mirror the files-list windowing in ArtifactsTab).
- **Keymap** (only when `isActive`): `j`/down = cursor down; `k`/up = cursor up; Shift+down / Shift+up = jump to next/prev FILE row, skipping dir rows (use `key.shift && key.downArrow`/`upArrow`; if none in that direction, stay put); Enter/right = expand a collapsed dir or open a file; left/`h` = collapse the dir, else move cursor to parent; `r` = refresh (re-read expanded dirs + re-read gitignore); `g`/`G` = top/bottom.
- **Gitignore-aware:** exclude ignored paths and always `.git/`. Mechanism: one-shot `git ls-files --cached --others --exclude-standard` run from `root` (use `Bun.spawn`/`Bun.$`), parsed into a Set of allowed relative paths, cached and only re-run on `r`. A directory is shown if any allowed path is under it. Falls back gracefully (show all but `.git`/`node_modules`) if git is unavailable.
- **Default-expanded:** on first mount expand `.charm/` and its direct children (tickets, proposals, kb, prompts, scratchpad); everything else collapsed.
- **Live updates + auto-reveal:** watch with `chokidar` scoped to `.charm/` plus currently-expanded dirs (NOT the whole project root). On change under an expanded subtree, refresh it. If a change lands in a collapsed dir, mark that dir row with a `(!)` badge until it is expanded/seen.
- **Binary rows:** dim (Ink `dimColor`) file rows for which `isBinaryFile` is true.

## Acceptance criteria
- [ ] Module type-checks under the project's `tsc`/Bun setup and exports exactly the three documented symbols (`TreeNode`, `isBinaryFile`, `FileTree`) with the documented signatures — no more, no less in the public surface.
- [ ] Lazy expansion: a dir's children are read only on first expand (`readdirSync(dir, { withFileTypes: true })` + `Dirent.isDirectory()`); collapse drops children from state.
- [ ] Visible-row flattening descends only into expanded dirs; a numeric cursor indexes it and the window scrolls to keep the cursor visible within `height` rows.
- [ ] Full keymap works only when `isActive`: `j`/down, `k`/up, Shift+down / Shift+up (jump to next/prev FILE row, stay put if none), Enter/right (expand collapsed dir OR open file), left/`h` (collapse, else move to parent), `r` (refresh + re-read gitignore), `g`/`G` (top/bottom).
- [ ] `onOpenFile(absPath)` fires on opening/selecting a file; `onOpenFile(null)` fires when the cursor lands on a directory — and never from render (see contract note).
- [ ] Gitignore-aware: one-shot `git ls-files --cached --others --exclude-standard` from `root`, parsed to a Set, cached, re-run only on `r`. `.git/` always excluded. A dir is shown if any allowed path is under it. Graceful fallback (show all but `.git`/`node_modules`) when git is unavailable or `root` is not a repo.
- [ ] Default-expanded on first mount: `.charm/` and its direct children (tickets, proposals, kb, prompts, scratchpad); everything else collapsed.
- [ ] Live updates: chokidar scoped to `.charm/` + currently-expanded dirs (NOT the whole root). Change under an expanded subtree refreshes it; change in a collapsed dir marks that dir row with a `(!)` badge that clears once the dir is expanded/seen.
- [ ] Binary file rows are dimmed (`dimColor`) where `isBinaryFile` is true; `isBinaryFile` does a null-byte / UTF-8 sniff of the first ~4KB.
- [ ] Renders without crashing on empty dirs, large dirs, and unreadable dirs (catch + skip).
- [ ] No edits outside `src/console/file-tree.tsx`. Tree only — `renderMarkdown`/viewer reuse is explicitly NOT this ticket's job.

## Edge cases & failure modes
- **Watcher lifecycle:** re-subscribe chokidar when the expanded-dir set changes and `close()` every watcher on unmount and on re-subscribe — do not leak watchers as the user expands/collapses. Mirror the `return () => { void watcher.close(); }` cleanup in `useFileTree`/`useFileContent`.
- **Cursor clamping:** after refresh, collapse, or a live update shrinks the visible list, clamp the cursor into `[0, visibleRows.length - 1]` so it can't point past the end (the same hazard ArtifactsTab guards with its scroll clamp).
- **git root vs. `root` mismatch:** `git ls-files` emits paths relative to the repo toplevel, which may differ from the `root` prop. Normalize both sides to the same base (resolve against the toplevel, or run `git -C root rev-parse --show-toplevel`) so the allowed-set membership test is correct — otherwise the whole tree can read as ignored and render empty.
- **Symlinked directories:** `Dirent.isDirectory()` is false for a symlink-to-dir, and following symlinks risks cycles. Treat symlinks as leaves (or skip) rather than recursing — do not follow them.
- **`isBinaryFile` on missing/unreadable files:** wrap the read in try/catch and return a sane default (treat as non-binary / let the open attempt surface the error) rather than throwing during a render pass.
- **Shift-arrow terminal support:** rely on `key.shift && key.downArrow`/`upArrow` per the spec; if a terminal doesn't report shift the row-skip simply won't fire — acceptable, do not add a fallback keymap.
- **`git ls-files` on a huge repo:** it's one spawn cached until `r`, so cost is bounded; just make sure the parse handles a large stdout and an empty/err exit without hanging the render.

Keep it idiomatic to the existing console code (Box/Text, `wrap="truncate-end"`, `useInput`, chokidar cleanup pattern).
