GOAL: Determine whether it is feasible to rewrite the Zed fork's color/theme scheme to match the charm studio design language, and if so, the recommended approach. ("ZZY" in the operator's request = Zed.)

---

## FINDINGS

**Feasibility: yes. Recommended mechanism: hybrid (theme JSON + CharmPalette struct).**

Full detail is in `.charm/proposals/PROP-zed-theme-charm-design.md`. Summary below.

### Palette source

The `.dc.html` mockups (`Charm Studio.dc.html`, `Orchestration Canvas.dc.html`)
contain the complete CSS custom property system for both light and dark modes --
every color value fully specified. The first mockup image is a palette swatch
showing the five core hues: #341C8C (deep violet), #657EBE (steel blue), #9475BF
(medium violet), #B4A3D9 (light lavender), #F2E1AE (warm cream/gold). The second
image is the canvas mockup confirming the light theme: pale lavender background,
deep violet orchestrator square, steel blue sub-orchestrator squares, purple agent
circles, rose-pink blocked circle.

### Zed's theme system

Themes are JSON files following a published schema. The active theme's colors are
read in any GPUI context via `cx.theme().colors()`. The `ThemeColors` struct covers
~15 structural chrome roles: backgrounds, borders, text levels, icon accent, tab
colors, git badge colors. `cx.theme().appearance()` returns Light or Dark.

### Token mapping split

13 of the ~30 charm CSS semantic roles map directly to `ThemeColors` fields:
backgrounds (bg-app -> background, rail-bg -> surface_background, panel ->
panel_background, canvas -> editor_background), borders, text tiers (text,
text_muted, text_placeholder), accent, icon_accent, and the done/git colors.

The remaining 19 roles have NO Zed equivalent -- they are the charm-specific
agent-status semantics: orchestrator fill (--orch), sub-orchestrator/worktree
fill (--blue family), blocked state (--blocked family), gold accent on dark
surfaces (--gold), idle tone (--idle), all edge colors (--edge family), on-orch
text/divider colors, canvas grid-dot, progress track, card/pop shadows, overlays,
mock badge. These are the roles that define what makes the canvas look like the
charm canvas rather than a generic IDE.

### Mechanism recommendation: hybrid

Option A (theme JSON only): Zed chrome re-themes but charm-specific colors scatter
as hardcoded hex strings across component files. Violates single-source goal.

Option B (extend ThemeColors): heavy -- schema changes, all existing theme files
need updates, upstream diff grows. Overkill for 19 fields used only by crates/charm.

Option C (recommended -- hybrid):
- `crates/charm/assets/themes/charm.json` -- built-in theme JSON setting all Zed
  ThemeColors fields for light and dark. Registered at init. Sets "charm Light"
  as default in `assets/settings/default.json`.
- `crates/charm/src/theme.rs` -- `CharmPalette` struct with LIGHT and DARK const
  instances. `CharmPalette::current(cx)` branches on `cx.theme().appearance()`.
  All charm component code calls this; no hex strings in component files.
- Result: one theme toggle re-themes the entire app. Zed chrome reads ThemeColors;
  charm panels and canvas read CharmPalette. Both layers update from one switch.

### Single-source-of-truth for charm panels and canvas

Yes -- `cx.theme()` is available in every GPUI render context including inside
crates/charm. The animated flow dots (`edge_flow` color) are evaluated via
`CharmPalette::current(cx)` at render time, so theme switches propagate during
animation without extra wiring.

### What does NOT map cleanly (worker notes)

- `strong` / `title` text levels: no Zed token; use as CharmPalette constants or
  assign `strong` to `text_accent`.
- `subtle` (third surface level): no Zed third-surface token; derive as rgba of
  orch at low opacity in CharmPalette if needed.
- Glow effects / box-shadow: GPUI has no box-shadow; approximate with layered
  translucent divs; defer full glow to v2.
- Canvas dot-grid (`--grid-dot`): CSS radial-gradient has no GPUI equivalent;
  options are a tiled Metal texture or drawn quads. Color comes from CharmPalette.
- Animated flow dots: Phase 3 already plans the imperative loop (`advance_dots`,
  `cx.notify()`); colors come from CharmPalette.
- Monospace font: Zed ships Zed Mono; set Geist Mono / Cascadia Code fallback in
  fork default settings.

### Files a build worker will touch

```
crates/charm/assets/themes/charm.json   create -- theme JSON
crates/charm/src/theme.rs               create -- CharmPalette struct
crates/charm/src/lib.rs                 register theme asset at init
assets/settings/default.json           set default theme to "charm Light"
crates/charm/src/sidebar.rs            import CharmPalette; replace placeholders
crates/charm/src/explorer.rs           same
crates/charm/src/canvas.rs (Phase 3)   main CharmPalette consumer
```

No changes to `crates/theme/` -- ThemeColors struct is untouched.
