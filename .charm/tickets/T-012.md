## Tasks

### Create docs/operating/concepts.md
A glossary-style concepts page defining charm's core terms. One short paragraph per term (2-4 sentences: definition + what it means in practice). Terms to define:
- **Session** — a UUID-keyed charm run; socket, pidfile, tmux layout, and agents are all session-scoped.
- **Ticket** — the unit of work: a markdown file with frontmatter (id, title, status, stage, depends_on, touches). The `.md` file is the source of truth; the SQLite DB is an index.
- **Stage** — the pipeline stage a ticket is in (generated, in_progress, done). Distinct from status.
- **Status** — the current state of a ticket (pending, ready, running, blocked, reviewed, complete, failed, cancelled).
- **Gate** — a human approval checkpoint. Three gates in the pipeline: after Discovery (Stage 0), after ticket review (Stage 2), and after testing (Stage 4). Gates are blocking.
- **Fleet** — the set of all live claude agents in a session (main + reviewers + workers + testers).
- **Worker** — an agent assigned to execute a single ticket. Runs in its own tmux pane.
- **Reviewer** — an agent that enriches a generated ticket (adds file scope, dependencies, detail) before workers run.
- **Tester** — an agent that checks a finished ticket's diff before the gate.
- **Orchestrator (main agent)** — the primary claude process that drives the pipeline: interviews, plans, tickets, spawns, gates.
- **COORDINATION.md** — the soft coordination layer: a shared file every worker reads before touching anything, showing what other agents are doing.
- **KB (knowledge base)** — `.charm/kb/`, a git-tracked cross-session store of architecture notes, decisions, and domain knowledge.
- **touches** — file globs in ticket frontmatter; the daemon uses these to serialize tickets whose scopes overlap.

After creating the file, add a link to it in `docs/README.md` under the Operating section (before getting-started, as it's a prerequisite read).
